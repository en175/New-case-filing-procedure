# 新立案流程 · 项目背景文档

> 用途：多线程 AI 协作 / 多项目并行时快速同步背景，减少重复沟通成本。
> 最后更新：2026-05-15

---

## 一、项目定位

广州仲裁委员会（广仲）在线立案流程重构项目。

将原有"填写复杂表单"的立案方式，升级为以 AI 辅助为核心的新立案流程：

- AI 对话引导生成申请书（替代表单）
- AI 自动提取已有申请书内容
- AI 判断案件类型，自动路由至调解或仲裁系统
- 案件评估报告承接路径选择，优先引导当事人选择调解

**甲方**：广仲（广州仲裁委员会）
**乙方**：我们（开发团队）
**系统归属**：调解系统是乙方开发，嵌入甲方案管系统左侧导航；仲裁系统是甲方自有系统。

## 四、核心业务逻辑

### 4.1 案件类型判断与路由

- AI 在申请书生成或提取完成后，判断案件类型
- 判断依据：后台可配置的 42 个调解案件类型（数据库字段，运营可维护）
- **42 类以内** → 案件数据推送至乙方调解系统
- **42 类以外** → 案件数据推送至甲方仲裁系统 API

### 4.2 路径选择的设计逻辑

- 页面展示路径选择（调解 / 仲裁）给当事人，但实际路由以 AI 判断为准
- 目的：给当事人参与感，同时系统层保证数据流向正确系统
- 仲裁路径设置三个辅助工具（游戏化问答 / AI 抗辩 bot / 时间线对比），均以引导当事人回流调解为目的
- 当事人坚持仲裁时，弹窗提示"已流转仲裁系统"并调用甲方仲裁 API

### 4.3 草稿自动存储

- 触发节点：**案件评估报告生成时（展示前）**，系统自动保存为草稿
- 草稿对应状态：申请书已生成/提取、评估报告已生成、路径未选择
- 草稿可见位置：甲方案管系统 → 我的案件 → 草稿
- 有效期管理：沿用甲方案管系统现有规则，乙方不单独设置
- 从草稿重新进入：直接回到案件评估报告页

## 五、主流程（文字版）

### 路径 A：已有申请书

```
当事人登录 → 进入在线立案登记
→ 选择「已有申请书」
→ Step2：上传申请书 PDF + 证据目录 + 证据材料
  （AI 后台：提取申请书字段 · 判断案件类型）
→ Step3：当事人信息确认（AI 预填）
→ Step4：被申请人信息确认（AI 预填）
→ Step5：案件信息确认
→ Step6：送达地址确认
→ 自动存草稿 → 案件评估报告 → 路径选择（见下）
```

### 路径 B：暂无申请书

```
当事人登录 → 进入在线立案登记
→ 选择「暂无申请书，AI 对话生成申请书」
→ 立案 bot：AI 对话采集信息 → 生成申请书草稿 → 用户确认/编辑
→ 跳转 Step2（申请书已自动上传）
→ 用户上传证据目录 + 证据材料
  （AI 后台：提取申请书字段 · 判断案件类型）
→ Step3：当事人信息确认（AI 预填）
→ Step4：被申请人信息确认（AI 预填）
→ Step5：案件信息确认
→ Step6：送达地址确认
→ 自动存草稿 → 案件评估报告 → 路径选择（见下）
```

### 评估报告后的路径选择

```
案件评估报告（材料完整度 / 风险提示 / 案件类型判断结果）
├─ 选择调解 → 推送调解系统 API → 调解申请提交成功 → 结束
├─ 选择仲裁 → 进入三路径辅助工具（可任选其一或多个）
│   ├─ 游戏化问答
│   ├─ AI 抗辩 bot（满3轮后解锁按钮）
│   └─ 仲裁/调解时间线对比
│   每个工具完成后均展示三个按钮：
│   ├─ 选择调解 → 推送调解系统 API → 结束
│   ├─ 继续仲裁 → 弹窗「已流转仲裁系统」→ 推送甲方仲裁 API → 结束
│   └─ 撤回案件 → 弹窗「已撤回」→ 结束
└─ 撤回案件 → 弹窗「已撤回」→ 结束
```

## 六、AI 能力点分布

| 节点              | AI 做什么                                  | 模型            | 输入                         | 输出                     |
| ----------------- | ------------------------------------------ | --------------- | ---------------------------- | ------------------------ |
| 立案 bot 对话采集 | 逐步引导用户输入申请信息，整合生成申请书   | DeepSeek V4 Pro | 用户对话轮次                 | 结构化申请书草稿         |
| Step2 申请书提取  | 上传后后台提取申请书各字段，预填 Step3-6    | DeepSeek V4 Pro | 申请书 PDF                   | 结构化字段               |
| 案件类型判断      | 对照 42 类规则，判断案件归属               | DeepSeek V4 Pro | 申请书结构化字段             | 类型标签 + 调解/仲裁判断 |
| 案件评估报告生成  | 综合材料完整度、类型判断、风险点，输出报告 | DeepSeek V4 Pro | 申请书 + 证据清单 + 类型判断 | 评估报告文本             |
| AI 抗辩 bot       | 模拟对方可能的抗辩角度，引导当事人评估风险 | DeepSeek V4 Pro | 案件信息                     | 对话式抗辩模拟           |

## 八、关键设计决策（已与甲方对齐）

| 决策                   | 内容                                                  | 原因                           |
| ---------------------- | ----------------------------------------------------- | ------------------------------ |
| 路径选择为引导性设计   | 页面展示选择按钮，但路由以 AI 判断为准                | 甲方要求，乙方已知晓风险       |
| 评估报告必须存在       | 两条路径均需经过评估报告再路径选择                    | 甲方明确要求，核心功能         |
| 仲裁路径设三个辅助工具 | 游戏化问答 / AI 抗辩 / 时间线对比，均以回流调解为目标 | 甲方需要展示调解优先的引导能力 |
| 草稿自动触发           | 评估报告生成时自动存，无需用户操作                    | 降低用户操作负担               |
| 42类规则后台可配置     | 运营可在数据库维护，不需要改代码                      | 业务规则会变化，不能写死       |

## 十、功能范围（当前确认）

**本期全链路包含：**

- 申请书准备方式选择（首页）
- 已有申请书：上传 + 分流 bot（AI 提取 + 对话核对 + 分类）
- 暂无申请书：立案 bot（对话采集 + AI 生成申请书 + 证据上传）
- 案件评估报告（AI 生成）
- 路径选择（调解 / 仲裁）
- 三路径辅助工具（游戏化问答 / 抗辩 bot / 时间线对比）
- 三个结果按钮（选择调解 / 继续仲裁 / 撤回案件）
- 草稿自动存储
- 调解系统 API 对接
- 甲方仲裁系统 API 对接

**本期不包含：**

- AI 判断置信度兜底机制（暂不设计）
- 草稿有效期管理（沿用甲方系统）
- 当事人身份认证体系（沿用现有登录）
- 后台 42 类规则配置界面（由后端直接维护数据库）
